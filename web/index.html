When a number means different things to different people, meetings turn into arguments about the data. This demo shows the fix: define each number once, report only from those definitions, and check the data before anyone sees it. Everything here is made up.

A report that looks right but is quietly wrong is worse than no report. These tests run on the data first, and a failure stops the refresh.

    How it works

    1. A small, made-up schema. Customers, products, regions and order lines, joined in one shared view so every measure starts from the same rows. It is not based on any real company’s database.
    2. The model is a plain file. Each measure is a name, a definition, an owner and a SQL query. A Python script runs those exact queries on seeded, made-up data and writes the results, so the SQL you can open above is the SQL that produced the numbers.
    3. Checks gate the report. Regions must add up to the company total, no row may be lost in a join, dates must run in order, and every measure must have a value.
    4. The page only reads the results. Plain HTML, CSS and JavaScript. Nothing is calculated in the browser except formatting.

    The same idea carries over to any BI tool. In a real engagement the model points at your system’s actual data, and the definitions are agreed with the people who own each number before anything is built.
